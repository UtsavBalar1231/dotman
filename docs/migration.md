# Migration

Importing an existing setup. Back to the [README](../README.md).

`dotman import [<source>]` converts a setup into a fresh repo. It never modifies the source and reports every entry as converted or needing action (exit 3 if any need it). `--dry-run` prints the report and changes nothing. `dotman init` with no argument detects the setups below and offers the import; `--no-import` skips that.

- **Legacy dotman** (`~/.dotman` from before 0.1.0): converts every commit, keeping parents, author, time and message. When a commit's message or author holds what the content guard holds, the import is one commit of the current state instead, and a note names each commit, rule and part, as for a git source below; `--keep-history` converts every commit anyway. `[dirs]` stays empty, because the first sync would capture every file in those directories: the directories the old store tracked are listed with the `dotman add` command for each, to run once you have added `[ignore]` patterns. `--overlay <source>` instead adds what the current repo lacks as one commit: it restores modes, and adds missing files only with `--include-missing`.
- **yadm, bare repos and vcsh, or any git URL**: for trees laid out relative to `$HOME`. yadm `##` alternates become variants, and its default-processor templates become `{tmpl}`. Other templates, yadm encrypt archives and precedence differences are reported. yadm links are replaced by `--swap`. Further vcsh repos go in through `--overlay`.
  - Only the history of the branch the source's `HEAD` names comes in: no other branch and no tag. A source whose `HEAD` is detached comes in on a new branch, `main`, and the report says so. So does a local source whose `HEAD` names a branch git refuses, such as `a.`, or cannot clone, such as `HEAD/x`: dotman reads that branch's commit from the source's ref files, without running git there, and fetches it. The new repo then has no remote, even from a URL, since sync would pull the source's own `main` and push to it; set a new, empty one with `dotman init --remote <url>`.
  - When a file, a file's name or a commit message in that history holds what the content guard holds, the import is one commit of the current tree, with no remote set, and a note names each file, rule and commit, and for a commit, the part that holds it: the message, the author or committer, a merged tag or the signature. Push it to a new, empty repo, not to the source: the source still holds the history the import left out and shares no commit with it. `--keep-history` imports every commit anyway.
  - A file in `$HOME` with the same bytes as the source and a stricter owner-only mode gets that mode in `[modes]`. When the source has its own `.dotman.toml`, that file is kept byte for byte and the `[modes]` lines to add are printed instead.
- **chezmoi**: plain files and symlinks only. Templates never run by default. `.chezmoiignore` is read as text, so any file it might exclude is reported, not imported. `--render-templates` opts in to running the real chezmoi after a warning.
- **Symlink farms** (Stow, dotbot, rcm and similar): content is read through the links. `--swap` then replaces the links with real files, recording them so a failure rolls back. Home-manager links into `/nix/store` are report-only.
